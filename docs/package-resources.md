# Package resources

For an unscoped package, use `lumine://<package-name>/<relative-path>` to load a file belonging to its loaded generation. The hostname is the manifest's `name`, regardless of its install directory or development link name. The package manager selects development, installed and bundled copies in its normal priority order, publishes that selection before package bootstrap, and removes it when unloading starts. A missing file never falls back to a shadowed copy. Deactivating a package leaves its loaded generation available; unloading it removes its resource route. Scoped package manifests load normally and do not receive directory-name hostname aliases.

Each application window has its own Electron session, so safe, normal and development windows can load different copies independently. Desktop sessions retain browser storage under their persistent window identity; tests, hidden windows and captures use temporary sessions. Renderer navigation starts a new resource generation; late lifecycle messages from the previous renderer cannot change the new map. Safe mode permits bundled package roots only. Package routes accept GET and HEAD and reject paths outside their package root, including filesystem links that escape it. Only the trusted file-based application origin and browser-initiated requests can read package roots; remote and opaque sandbox preview origins are rejected using Electron's native `initiatorOrigin`. The package lookup is an in-memory map, with no synchronous filesystem probing or directory search on the request path.

Put personal images and fonts in `~/.lumine/assets` and address them directly with `lumine-assets://local/<relative-path>`. Electron's native `protocol.registerSource()` serves this fixed directory, including MIME types and byte ranges, without entering the JavaScript main thread. No other hostname or directory is mounted on that scheme, and directory index responses are disabled.

Live package resources use `protocol.handle()` with Electron's native fetch-body relay. Electron 45 creates immutable native source snapshots for each renderer document: unregistering and re-registering a `protocol.registerSource()` does not update an already open renderer. Using that API for a mutable package map would leave installed, unloaded or replaced packages pointing at stale copies until a window reload. The fixed personal-assets source and mutable package map deliberately have separate schemes.

# Brand art

The README banners and desktop wallpapers use the website's warm neutral palette, full-width rules and gold application mark. The logo comes directly from `resources/app-icons/lumine.svg`; the banner description comes from `package.json`.

| Asset                                 | Size        | Appearance              |
| ------------------------------------- | ----------- | ----------------------- |
| `resources/brand/banner.png`          | 1600 × 600  | Light README banner     |
| `resources/brand/banner-dark.png`     | 1600 × 600  | Dark README banner      |
| `resources/brand/wallpaper.png`       | 1920 × 1080 | Dark desktop wallpaper  |
| `resources/brand/wallpaper-light.png` | 1920 × 1080 | Light desktop wallpaper |

Each PNG has a generated SVG sibling. The README selects its banner using the reader's color preference. PNGs preserve the exported typography on every platform; SVG text uses Segoe UI and Consolas, so their appearance depends on the viewer's installed fonts.

To regenerate only these assets on Windows:

```sh
npm run generate:branding -- --brand-only
npm run check:branding -- --brand-only
```

The layout and palette live in `script/brand-art.js`. The existing branding generator renders the SVGs through Electron and checks their generated files. It requires Segoe UI, as the Windows installer artwork does. Use `--out <directory>` to preview an export elsewhere. A full branding run also regenerates these marketing assets.

Application screenshots are separate: capture them from running Lumine. A banner or wallpaper is graphic design, never a substitute for an editor screenshot.

## Windows installer

The installer sidebar and header are generated by `script/generate-branding.js` from the same canonical logo and the light palette in `script/brand-art.js`. The sidebar uses a warm neutral surface, rules spanning its framed panel, and a gold accent. Both graphics have a thin inset frame and white margins that separate them from the native page edges. The header leaves its bottom edge white so it does not duplicate NSIS's horizontal separator. Both use Segoe UI. The generator verifies the white outer edges, sidebar surface and gold mark before exporting.

The NSIS assets are opaque 24-bit BMP files rendered directly from the vectors at 300% resolution: `resources/win/installerSidebar.bmp` is 492 × 942 pixels and `resources/win/installerHeader.bmp` is 450 × 171 pixels. Their logical fields remain 164 × 314 and 150 × 57 pixels at 100% scaling. The uninstaller reuses the sidebar. Regenerate and verify only these two assets with:

```sh
npm run generate:branding -- --installer-only
npm run check:branding -- --installer-only
```

Add `--out <directory>` to preview the generated files elsewhere. The installer-only mode does not render application icons, banners, wallpapers or README screenshot compositions. It cannot be combined with `--brand-only` or `--gallery-only`. Generation is an explicit maintenance command; packaging uses the committed assets.

`resources/win/installer-art.nsh`, included by `installer.nsh`, replaces MUI2's header and welcome/finish bitmap-loading hooks with a control-sized GDI `HALFTONE` resample. It reads the actual control dimensions, loads the full-resolution source, then draws into a destination bitmap without enlarging the dialog. This avoids both magnifying the old 1× raster on high-DPI displays and the jagged small text produced by `LoadImage`'s default resizing of a larger raster. Temporary DCs and source bitmaps are released immediately; MUI retains its usual ownership of welcome/finish images. The native header bitmap lives for the wizard's process, matching MUI's existing header loader contract.

## README gallery

The original lossless PNG captures live in `.github/gallery/view-1.png` through `view-4.png`. Capture the application's rectangular content area at default editor font settings, excluding the operating system's window border and rounded corners. Their captions and capture context are recorded in `.github/gallery/captures.json`. Keep the captures authentic: replace them with new captures from the application, never with reconstructed UI or generated editor views.

Before capture, move the pointer away from the dock edges and wait for their reveal buttons to hide. Do not capture a transient dock button, tooltip or resize state; clear it through the application's normal interaction before taking the screenshot.

Use normal mode for captures so the application displays its gold logo. In an isolated capture process, set `LUMINE_DEV_MODE=0` and omit `--dev`; do not change the developer's permanent environment. Verify `lumine.window.isDevMode()` and `lumine.window.isSafeMode()` are both false before capturing.

The gallery generator fits those unaltered captures onto four separate numbered panels with matching backgrounds and full-height rules. A rounded clipping frame gives the editor clean corners without bringing the desktop or system window border into the capture. Each panel has light and dark versions. The README uses separate `picture` blocks without a surrounding `div`, leaving a small natural gap between images. All eight panels are generated from the same four captures:

```sh
npm run generate:branding -- --gallery-only
npm run check:branding -- --gallery-only
```

The composition lives in `script/gallery-art.js` and reuses the banner palette. The website can link directly to the repository's original captures or gallery images; it does not need another copy of them.

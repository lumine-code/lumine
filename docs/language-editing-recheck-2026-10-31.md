# Language editing recheck, 2026-10-31

Independently rechecked all 78 language packages after the [indentation audit](grammar-indentation-audit-2026-10-31.md) and [editing-settings audit](language-settings-audit-2026-10-31.md). Reviewers changed language groups and exercised actual editor input, including incomplete parser recovery, repeated Enter, explicit reindent, aliases with invalid suffixes, isolated package loading and general source settings. This found additional behavior gaps in 37 language packages and the automatic-pair provider. The earlier passing suites did not cover these states; this recheck adds durable regressions for the confirmed failures.

## Corrected behavior

Delimiters recovered from unfinished string, raw-text and verbatim contents no longer open extra code indentation. Recovered multiline payloads retain their authored whitespace during explicit reindent. These guards are tied to literal evidence, with complete-literal/real-container and active-interpolation controls; ordinary incomplete code containers continue to indent.

JavaScript and TypeScript switch bodies open a new level only after a trailing case/default colon. Multiline JSX and TSX tags anchor the following body or self-closing continuation to the tag owner. Typing an inline attribute's closing delimiter keeps the attribute row's own indentation.

Interpreter detection requires a supported executable in interpreter position. Modelines require complete aliases, rejecting lookalikes such as cppish, makeup and language-name suffixes. Valid LF/CRLF line endings remain accepted before following code. Objective-C header detection skips supported comment/include preambles and requires a live marker before ordinary code, avoiding markers inside comments and raw strings. Explicit user file associations retain precedence.

Comment metadata is verified with general source settings active and packages loaded independently. Formats with no comments opt out explicitly; Go subformats, notebook JSON/JSON5, ERB hosts, IPython and Mustache retain their native or comment-free policies. AutoHotkey line comments remain available without advertising line-restricted block syntax as an arbitrary inline snippet wrapper. Known embedded-language comment policies remain intact. Unknown Markdown fences retain the existing host comment fallback because no installed language supplies native metadata.

Automatic pairs now follow exact per-cursor scopes inside installed embedded languages. With worker syntax, an unavailable or obsolete scope result skips immediate automatic bracket/quote edits while ordinary typing continues. Mixed selection policies leave immediate bracket/quote wrapping to ordinary input. Mode, syntax epoch, document revision and cursor positions own each scope result; configuration changes invalidate resolved policies. Scoped user overrides remain effective, and matching/navigation and explicit bracket commands keep their separate policy.

## Verification

Complete suites were rerun for all 37 changed language packages: 1327 specs, no failures. Their query/spec/license payloads, lint and formatting checks pass; formatting checks distinguish committed LF source from unchanged CRLF checkout conversion. Prior modeline safety tests remain alongside the suffix and multiline-prefix regressions, including long failed token sequences. Retained sources keep their previously verified exact revisions and suite results. The current 78-package inventory contains 2161 full-suite specs.

Separate actual-source replay passes 84 literal-boundary cases and 192 multiline-modeline cases (96 valid aliases and 96 invalid-suffix controls), with unchanged grammar/query hashes throughout each replay.

The provider passes 282 full default-mode specs and 33 targeted worker-mode specs, including embedded Haskell/JSON, empty fences, mixed selections, scope changes, user overrides, pending analysis and atomic input publication. Ruby interpolation inserts the hash immediately, then uses exact syntax and scoped settings to add braces only while that accepted input still owns its revision and selection. Cancelled input, redirected selections, changed source text and configuration changes cannot claim or restore old text. Independent review checks lifecycle, stale scope cancellation and interpolation ownership. Its reviewed development-audit exception remains documented in the [provider audit policy](https://github.com/lumine-code/bracket-matcher/blob/1e3f7be73d521be0d88999784148c3bf3ec26b2e/docs/dependency-audit.md).

Editor validation covers 268 focused query/indentation/paste specs, 22 existing worker integration specs and all 429 Node Tree-sitter/runtime tests. The unchanged integration suite caught the cold-scope Ruby regression; production interpolation now passes that test. Query compilation covers all 119 workspace descriptors and 43 bundled descriptors. All 108 Wasm assets retain their parser sources and pinned builder compatibility. No parser binary or registry dependency version changed.

# Syntax analysis ownership

The editor uses one worker per window to own Tree-sitter parsers, WASM trees, injection layers and queries. The renderer owns the authoritative TextBuffer, selections, undo history and presentation. The production renderer holds no syntax tree. The inline backend remains available for parser tests and controlled performance comparisons. The Jasmine runner defaults to inline for engine-level fixtures; set `LUMINE_SYNTAX_EXECUTION=worker` to run package scenarios against the application backend.

The editor manifest declares the optional packages used by integration specs in `specPackages`. A full workspace resolves them from sibling repositories. In a standalone checkout, run `node script/install-spec-packages.js --package . --home <isolated-home>` and run tests with `LUMINE_HOME` pointing at that home. CI provisions it automatically. These test packages remain outside the bundled distribution.

## Document synchronization

A document opens from an immutable text snapshot, sent in strings of at most 65536 UTF-16 code units. Subsequent edits preserve their exact offsets and source revision. Small transactions take one message; larger transactions use acknowledged packets containing at most 128 changes and 65536 inserted code units. A large individual insertion is split into text packets. The worker applies the complete transaction atomically and keeps analyses waiting until it commits. Its mirror does not retain editor undo history.

Restored tabs select their grammar during document restoration. Their worker mirror opens when any pane first requests visible coverage or an operation requests syntax. The initial transfer reflects the latest renderer text, path and configuration, including text recovered from the saved session and any intervening edits. Reading the grammar or checking for a settled syntax token is observational.

Responses identify the source revision and syntax generation. Grammar, query, configuration, path and root-range-policy changes invalidate pending requests even when the text is unchanged. Closing a document cancels its streams and releases its worker session. An unexpected worker crash permits one recovery from authoritative renderer snapshots; another crash disables analysis instead of entering a restart loop. The idle worker terminates after the last document has been released.

With worker syntax, automatic indentation prepares the complete editing operation privately before publishing text, whitespace and selections in one editor transaction. The authoritative source and undo history remain unchanged while planning; cancellation, obsolete versions and failed analysis never expose a partial correction.

Interactive input uses `mode.prepareInputIndentation({ changes, ranges, tabLength, options, signal, isCurrent })` and receives one complete `{ kind: "ready", levels }` reply. The compact request contains at most 128 changes, 65536 inserted UTF-16 units and 128 requested rows. The renderer validates every returned row before applying the plan to the private draft in a single in-memory batch. Larger mutations, moves and pastes use the acknowledged `scanPreparedIndentation()` stream and its staged application. Both paths publish the final text and selections together.

Typing plans use one immutable syntax forest and one complete proposed source. For eligible whitespace insertions, a private input snapshot borrows the settled pre-edit root and relevant embedded trees without copying or parsing them. A shared change map projects node geometry lazily into the proposed source. Native structural queries and their token predicates run on the original trees; the private node view supplies projected positions and proposed text to the indentation and scope predicates. Node starts follow text moved by an insertion, while node ends exclude whitespace inserted at that exact boundary. This keeps Enter after a completed one-line suite distinct from Enter before its body. Thus splitting several Python suites preserves their `if`/`elif`/`else` ownership even though the raw, unindented draft would parse as broken clauses. This projection is a typing context, never a parsed AST for the new source, and is never published as document syntax.

Requested rows are resolved in buffer order without changing the proposed source. A compact virtual history supplies the final absolute indentation of earlier planned rows, including retained suffix whitespace and hard-tab alignment. Insertion-time blank-row baselines carry `comparisonRowIndentCaptured`; only a changed planned prefix invalidates that captured baseline. Explicit comparison overrides remain intact. The worker and inline backends share the resolver and projection. An inline multicursor insertion returns its completion promise when indentation is asynchronous, and remains tracked by `editor.whenGrammarSettled()`. The UI input queue therefore preserves Enter, typing and Backspace order in either backend. Cancellation or failure also cancels the already waiting input sequence; it cannot replay those keys at an independently moved cursor. Fresh input after that sequence drains uses the current cursor normally.

Grammars that can create indentation-relevant embedded languages can prove each affected owner stable through a grammar-owned input edit policy. If that proof declines, or a root-range provider controls ownership, the planner discovers one complete indentation-relevant candidate forest. Its current owners and ranges govern routing. Unambiguously matched owners keep the original typing context, while new or changed owners use their freshly parsed trees. A new injection elsewhere therefore cannot detach an existing Python elif from its original owner. Token-changing operations and missing or incomplete baselines use the ordinary parsed candidate. All paths query one fixed forest with the same virtual history. Paste and explicit reindent retain their own structural semantics. No input plan applies a prefix and reparses before deciding the next cursor. Parsing work can depend on source size and embedded-language topology, but adding cursors does not add complete candidate parse cycles.

A grammar opts into ownership-sensitive projection with `treeSitter.inputEditPolicy`, a module path relative to its grammar definition. The synchronous module receives a frozen `{ before, oldText, newText, after, previousLine, row, column }` context for each sequential insertion; `oldText` is empty, and each line and insertion is limited to 4096 UTF-16 units. Returning literal `true` proves that this edit cannot create, remove or reroute an indentation-relevant embedded language. Exceptions, promises, missing policies and uncertain boundaries require the complete ownership-discovery path. This policy never chooses indentation levels: the existing indentation query remains responsible for those decisions. IPython supplies a conservative policy for ordinary Python statements, declining scaffold controls, strings, comments and uncertain continuations.

A projected plan allocates no native trees or parsers. Closing it clears its private query caches, node views and scope state and releases references to the borrowed parent trees; those trees remain valid for their other consumers. A parsed candidate captures available published syntax and reconciles its new embedded-language topology before reusing a baseline; unmatched layers parse fresh. Private candidate analysis failures propagate as errors rather than successful cancellation.

While interactive indentation is preparing, the worker pauses presentation queries at their cooperative boundaries. Offscreen warming, streamed tiles, timeout retries and provisional previews resume after the input reply can be delivered. A private session's input-priority lease covers initialization and every acknowledged result packet until the session is released or invalidated. Fold preparation yields after a 4 ms allowance and checks cancellation and input priority before continuing. Waiting presentation requests retain independent cancellation; failed, cancelled and overlapping input requests release the shared priority barrier without adding a debounce delay.

Private input candidates also carry an explicit parser priority ahead of preview, focused-document and background parsing. They keep their own buffer and session identity rather than borrowing focus from the parent. This priority applies to root and embedded parse slices; scheduler aging still grants overdue background work service. Bulk indentation keeps its ordinary scheduling policy.

Interactive whitespace input captures an already-current forest immediately when available. While it needs a newer parent forest, the plan raises that parent revision's parse priority and wakes its quiet-period wait. The claim ends when the baseline is captured or the plan is cancelled. Text and grammar changes supersede the claim. The same rules cover compact and streamed input.

## Scheduling and resource budgets

Parsing resumes in slices under one shared 4 ms allowance per worker turn. A suspended parse occupies no concurrency slot. The scheduler rechecks the active document between slices, preserves FIFO ordering at equal priority and gives waiting work a turn after 100 ms. Injection layers share the same scheduler and revision budget as their root. These are cooperative allowances: Tree-sitter must reach a progress callback before yielding, so they are not a hard upper bound on one native call.

Each revision has a 30 second active parsing allowance, excluding scheduling, transport and consumer waits. The runtime also stops a parse when growing WASM memory reaches 85% of its configured maximum, before the allocator's hard limit where possible. Diagnostics distinguish `parse-budget`, `memory-pressure` and a fatal runtime failure. Memory measurements describe allocated linear-memory capacity, not live allocations or an individual document's retained memory. A runtime that reserves its full capacity at startup cannot use growth as a pressure signal and retains the hard-failure path.

Closing a session that caused at least 64 MiB of observed capacity growth requests recycling when the runtime still holds at least 512 MiB. Recycling waits for 750 ms without foreground interaction and for outstanding requests to finish, then reconstructs surviving documents from their authoritative snapshots. Fatal failures and memory pressure use immediate recovery because their runtime cannot safely continue. Ordinary close-time recycling does not consume the unexpected-crash recovery allowance.

Queries have separate work limits: by default 25 ms, 4096 in-progress matches, 16000 returned results or captures, and 65536 UTF-16 code units for an individual predicate text read. Injection query predicates allow up to 1048576 units so ordinary large comments can retain exact language routing; extracted language names and scope predicates keep the smaller cap. Presentation permits a 50 ms query pass in the worker to accommodate dense ordinary source. Query result limits are checked after the binding collects results; they are not an allocator limit. Source windows and native progress checks bound the preceding work. Regex predicates and custom JavaScript callbacks must still be written to terminate promptly. Text predicates either inspect the complete permitted text or fail; they never receive a truncated prefix with altered semantics.

An exhausted exact query reports `ERR_SYNTAX_QUERY_BUDGET`; an editor or buffer analysis returns `null`, and consumers discard any staged output. Foreground presentation retries a timeout once after yielding, using the same deadline. Persistent timeouts and structural limits publish limited coverage with a reason. Visible timeout-limited paint gets up to three delayed recovery attempts after 100, 500 and 2000 ms, behind missing foreground coverage. Hiding or releasing the view cancels its wakeup. Edits and syntax changes discard old attempts, and revisiting an exhausted range grants a new bounded cycle. Optional prefetch and warming query for up to 8 ms per pass and yield before retrying a smaller row range. A single-row timeout pauses warming and leaves that range eligible for the full foreground budget when it becomes visible. Scope event assembly yields during dense tiles. Structural limits never retry automatically. Incomplete query results never enter the exact-result cache. Failure to establish required injection topology makes document analysis unavailable.

Deadlines gate admission, native progress and further predicate work. A complete bounded result is not retrospectively discarded because its completion check ran late; cancellation and structural limits still invalidate it. A timed-out injection window can retry twice, yielding and rechecking its source identity before each attempt. Each attempt stages its records independently and merges only on completion. Small exact scope queries allow one fresh attempt. None of these retries increases a query's individual deadline or retries a text, match or result limit.

## Analysis failures

Parser initialization and settlement failures quarantine the affected document. Its selected grammar and language settings remain intact, but the replacement language mode owns no syntax session, highlighting or syntax folds. Editing and saving remain available. Pending analyses finish with `null`, and subsequent requests return `null` without queuing work. Package programming errors still reject; a valid analysis returning an empty array remains distinct from unavailable analysis.

Worker-owned background updates report failures through the same structured channel even when no view or analysis request is waiting. A current failed update produces one owner notification, without a raw console error; a newer revision can supersede a queued obsolete failure. Exhausted required query work reports `query-budget` with its specific reason. Private previews retain their own failure state and propagate errors that require recovery of the shared runtime.

An Emscripten abort or WebAssembly runtime trap poisons the entire worker runtime. The worker reports a structured diagnostic with the current document, operation, revision, grammar and available memory measurements. The renderer quarantines the responsible document, terminates the worker and restores the other documents from current text snapshots. When attribution is unavailable, all affected documents are disabled rather than replaying unknown failing work. A memory-limit diagnostic means the runtime stopped with its linear memory at the configured maximum; it is not inferred from the text `Aborted()` alone. Runtime stderr is retained in bounded diagnostics rather than printed repeatedly.

Each quarantined document receives one warning with diagnostic details and a Retry Analysis action. Edits, scrolling and configuration updates do not retry it automatically. `editor.retrySyntaxAnalysis()` explicitly restarts from current text and returns whether a retry was started; changing to another grammar also replaces the failed mode. Closing or replacing that mode dismisses its warning.

`editor.getSyntaxAvailability()` reports `{available: true}` for enabled analysis, `{available: true, deferred: true}` for a restored document whose worker session has yet to start, `{available: false, reason: "none"}` for None and `{available: false, reason: "failure", failure}` after an infrastructure failure. Automatic consumers can inspect `deferred` without starting work and resume on the existing `onDidTokenize` event. Explicit `whenGrammarSettled()` requests start analysis and wait for full readiness. `editor.onDidChangeSyntaxAvailability(callback)` observes language-mode replacements. Consumers cancel pending UI work and clear decorations or staged stream output when availability becomes false. This contract applies to every split sharing the document.

## Package analyses

Use `editor.analyzeSyntax(modulePath, method, params, options)` for operations tied to an editor, or `buffer.analyzeSyntax(...)` for shared document data that must survive closing one split. The module path must be absolute. Params are cloneable data. An invocation returns a promise; `null` means it became obsolete. Parse failures also return `null`, while programming errors reject the promise. Editor analyses include pending automatic indentation before acquiring syntax. Consumers must still validate selections and their own UI or service lifetime before applying an answer.

```js
// Renderer-side package code.
const ranges = await editor.analyzeSyntax(
  require.resolve("./syntax-analysis"),
  "findCalls",
  { name: "print" },
  { signal },
);
```

```js
// syntax-analysis.js: runs beside the parser, without DOM or editor globals.
exports.findCalls = (context, { name }) => {
  const root = context.getRootSyntaxNode();
  if (!root) return [];
  return root
    .descendantsOfType("call")
    .filter((node) => node.childForFieldName("function")?.text === name)
    .map((node) => ({ start: node.startPosition, end: node.endPosition }));
};
```

The read-only context provides document reads through `context.buffer`, editor-style text and coordinate helpers, the root node, node lookup, query capture groups, scope ranges, comment delimiters, fold queries and indentation hints. `context.signal` is aborted when the invocation ends. Do not retain nodes, cursors, context methods or unfinished asynchronous work beyond that lifetime. Poll the signal and yield during long JavaScript loops. DOM operations, editor mutations, package-manager access and renderer closures belong outside the analysis module.

Renderer methods that expose raw nodes or query captures are restricted to the inline backend and throw with worker syntax. Move that computation into an analysis module instead of requesting cloned nodes or relying on an empty result. The same pure module runs beside the inline parser in comparison tests.

Return plain data, arrays, maps or typed arrays. Point and Range values become plain coordinate records. WASM nodes, functions, accessors and other class instances are rejected rather than transported as unusable handles. Convert coordinates with `Point.fromObject` or `Range.fromObject` when the renderer needs those classes.

For large results, the analysis receives `{ signal, emit }` as its third argument. Await every `emit(packet, transferList)` and keep each packet bounded. The renderer supplies `options.onChunk(packet)`, which may return a promise. Acknowledgement follows that promise, so decoding and consumer work participate in backpressure. The promise returned by `emit` resolves to the consumer's cloneable acknowledgement value. This lets a worker scan resume from a renderer-owned handler's consumed offset without serializing that handler. Do not accumulate raw packets and then decode the whole result in one final renderer loop. Return a small completion summary; discard accumulated output if the final result is `null`.

`context.scanGrammarQueryCaptures(type, { batchSize })` is an async iterator over `{ grammar, captures, layerId, last }` packets. It scans 8192-code-unit source windows and emits at most 256 captures by default; `batchSize` accepts 1–4096. Captures remain native nodes inside the analysis owner. Consume and convert them before requesting the next packet, and release per-layer state at `last`. Genuine duplicate captures are preserved. Edits, grammar or query replacement, cancellation and query exhaustion terminate the scan instead of returning a successful partial result. The symbol provider uses this path to retain plain symbols and active containers rather than an array of every raw capture.

`context.getGrammarQueryMatchesAtBufferPosition(type, position)` returns groups of `{ grammar, matches }` from language layers whose extents cover the point. The query window covers the adjacent UTF-16 units and preserves surrogate pairs and CRLF. Each match keeps the accepted associated captures, including names elsewhere in a declaration. A consumer can use these matches for a local result when its query contract guarantees that the result needs only those matches. The standard query budgets and cancellation rules apply.

Bulk indentation uses `mode.scanSuggestedIndentation(ranges, tabLength, options)`, an async iterator over batches of `[row, level]` entries. Ranges are ordered, disjoint, inclusive row pairs; a `null` level means preserve that row. Options include `batchSize` (1–4096, default 256), `signal`, `isCurrent` and `preserveLeadingWhitespace`. The iterator preserves virtual indentation across packets and disjoint ranges, including references to distant earlier rows. It retains changed levels in compact pages rather than building a whole-document Map. Worker transport holds at most one unacknowledged batch. Breaking iteration cancels the producer; source or configuration changes abort it. Apply the completed plan through a cancellable editor transaction that rolls back if the stream fails.

## Exact semantics and presentation

`getScopeDescriptorsForBufferPositions` and `getCommentDelimitersForBufferPositions` query many positions in one bounded operation, including positions outside visible rows. They return `null` when superseded. Use them for semantic decisions. The worker can complete batches of up to 256 points once the host tree and all relevant embedded layers are current. Comment delimiters consider both the requested point and the first nonblank character of its row. Larger batches and injections that escape their owner use whole-document settlement. Fold, syntax-scope, token, paragraph and comment queries can resolve asynchronously with worker syntax. Await the result before changing editor state. `getSyntaxSnapshotToken()` supplies an opaque identity for settled semantic caches and returns `null` while the complete forest is pending.

Exact point lookups query one UTF-16 character, extending across a surrogate pair or CRLF when necessary. Enclosing captures and covering injection layers retain their semantics even when they have no boundary inside that window. Scope range adjustments can resolve conservative finite-width regexes through bounded source slices, such as finding the first opening brace of a large CSS rule; unsupported expressions retain the full-text guard. Grammar predicates should inspect a small structural token when they need only a prefix: Python string classification reads `string_start`, while keeping its native filtering and complete body scope.

Synchronous scope reads remain presentation reads: they use prepared coverage and may show retained scopes while a new revision is being parsed. They cannot be used to claim an exact AST result. Rendering requests belong to their view owner, including a separate minimap owner. `requestHighlightingForScreenRows(owner, start, end)` prepares the view; pass that owner to `tokensForScreenRow` and optional `maxTokens` and `maxColumns` to bound token conversion and source materialization. Auxiliary surfaces such as the minimap request only the prefix they actually draw. Release coverage with an empty range. Scope boundaries stream in packets of at most 4096 events. A range contains at most 128 rows and normally at most 16384 UTF-16 code units; row-oriented fallback on a pathological single row remains explicitly limited. Visible text uses full-document column windows of at most 8192 UTF-16 units, including soft-wrapped rows and horizontal virtual windows. These windows never claim coverage for the rest of the row. Fold interiors are excluded while their boundary context is retained. Each completed range publishes immediately, and its acknowledgement selects the next missing range from live requests. Visible editor splits precede their prefetch, followed by minimap requests and single-line measurements. Measurement reads do not request prefetch. The surrounding lead follows approximately 120 ms of measured row movement, bounded between 128 and 1024 rows, with 128 rows retained behind. Scrolling renders the current destination immediately with available scopes and requests its missing coverage without awaiting it. Horizontal virtual windows follow the same rule. Overlay thumb updates only change their transforms, independently of token DOM replacement and without native scroll-position readback. Unchanged coverage is reused, and highlighting does not wait for scrolling to stop or for a minimap batch to finish. Row reads locate scope boundaries with binary search and reuse bounded lazy checkpoints instead of replaying the whole tile prefix for every row.

The scope iterator uses the next screen row's source position as the end of a wrapped render range. A horizontal window supplies its own end position. The minimap can prepare scopes for a single wrapped row with a read bounded by that row's source interval.

Exact viewport paint can begin once the host tree, its injection topology, and every required embedded layer are current for the requested range. The parser keeps each language's complete input context, including the disjoint regions of combined injections. Intersecting layers receive priority while a visible request waits. Injections whose content can escape the indexed owner require whole-document settlement. Whole-document analyses and fold preparation for early tiles still await the complete forest. Moving to a disjoint viewport cancels the previous view's pending paint when no primary view still needs it.

After an edit, each visible retained injection can advance independently once its parent has reconciled the current topology. Adoption uses the same proof as whole-document settlement. The previous tree must match the new included ranges after applying the exact edit journal, and those edits must leave its parsed content intact. A combined injection checks every included range. A pending or unproven layer follows the ordinary settlement path.

Existing colors remain visible while replacement work runs. If a visible request is still waiting after a 4 ms grace period, it may independently parse a complete document of at most 16384 code units. The preview retains the source path and full lexical context, including comments, strings and injected languages beginning outside the viewport. Provisional colors fill only uncached gaps. An incomplete preview query publishes no coverage. Exact parsing supersedes the preview, and edits or disposal release its private tree. Explicit root-range policies use the owning document's syntax.

Paint fragments carry `quality: "exact" | "provisional" | "limited"` and an optional reason. The worker mode's `getHighlightingStatus()` reports current coverage separately from retained colors. Matching revision, grammar generation and presentation identity are required before coverage can be called ready. Those identities do not prove that two paint results are equal: publication compares effective scope stacks and invalidates changed screen rows even when the incoming tile overlaps already prepared coverage. Identical rows keep their cached screen lines, and provisional paint neither rebuilds retained rows nor consumes pending exact invalidations. A limited result cannot replace exact colors with the same revision, grammar generation and presentation identity; its uncached or non-exact remainder is still recorded, so budget exhaustion cannot cause an endless request loop. Coverage and gap lookup use the same identity and optional quality filters. A completed full AST does not imply that an arbitrarily long line has complete highlighting. Semantic consumers acquire exact syntax for the ranges they depend on.

Bounded regular-expression matching preserves the pinned binding's predicate order, quantifier and negation semantics. Finite-width edge predicates inspect only the required source prefix or suffix of a large node. Unbounded expressions and uncertain negative results keep the normal text/deadline limits; no truncated string is treated as a complete node. The same bounded matcher supplies scope adjustments.

Token DOM can be retargeted across disjoint viewports while retaining its full CSS ancestry. The previous owned subtree is validated before mutation. Inline styles, foreign DOM, focus, pointer interaction and excessive nesting retain the existing construction path. Text-node references and pixel caches follow the replacement line identity. Layout visibility and horizontal-window bounds are read only when their work queues require them. `TextEditor.batchDecorations(callback)` combines marker-layer and decoration-update notifications without creating an undo transaction; individual marker events remain synchronous.

The renderer retains up to 256 scope fragments under a 512000-event allowance and an estimated 32 MiB budget for the active document, including checkpoints and pending edit metadata. Inactive documents use 128000 events and 8 MiB; losing focus immediately evicts unprotected fragments over that allowance. Focus restores background warming within the larger allowance. Primary visible ranges and the packet being published remain protected, so required coverage may temporarily exceed the estimate. The query cache has a separate estimated 2 MiB allowance. Neither estimate measures native WASM tree storage. When foreground requests are satisfied, the worker prepares missing 128-row fragments near the visible editor, within 16384 rows in each direction. Optional warming pauses when it causes eviction or exceeds its allowance, preventing repeated requests for coverage that cannot remain cached. A genuine viewport or source change permits new warming. Each packet acknowledgement rechecks current foreground requests. Folded views do not warm hidden interiors, measurements do not initiate background preparation, and hiding an editor releases its viewport request. Edits before a retained fragment accumulate a row offset instead of walking all its scope events; reads translate only consumed events, while partial replacements materialize the affected fragment.

For multiline completion edits, track inserted ranges through additional edits and call `autoIndentBufferRowsAtRows(rows, { groupWithPrevious: true })` after the transaction. The sparse plan applies once against one revision. Independent edits or indentation-setting changes cancel the correction. Automatic newline indentation follows marked rows through continued typing in the same editor and remains part of its undo operation.

Wheel input, scrollbar gestures, programmatic scrolling and cursor or search autoscroll update the viewport independently of syntax readiness. A cold destination displays its current text with available scopes; missing colors arrive asynchronously. Wheel input renders within its animation frame, and scrollbar input renders synchronously. Rendering requests track the current viewport, so late results for an earlier destination can update cached scopes but cannot move the viewport back. Colors arriving for mounted lines update those lines immediately, preserving their scroll transform and decorations. Prefetch publishes only uncovered or changed ranges; already current coverage and touching offscreen ranges do not redraw the viewport.

A streamed color tile publishes before its fold queries. Fold lookup runs while the existing color acknowledgement is in flight and sends a separate bounded notification; it does not add another acknowledgement round trip. Fold notifications carry the session revision, grammar generation and presentation identity, and obsolete replies cannot roll the renderer generation back. Foldability updates refresh gutter state without invalidating colored screen lines.

Whole-document fold commands and divided folds whose matching boundary lies outside the local window use a cancellable scan over bounded source windows. The scan keeps open boundaries across windows and caches the complete result for the current tree and query. It yields to input requests. A distant gutter lookup runs separately from the color request so it can finish after the viewport has painted, while an explicit fold command applies its completed ranges together.

## Grammar modules and root ranges

Register dynamic injections through `lumine.grammars.registerSyntaxModule(require.resolve("./injections"), { method: "register", args: [] })`. Its exported factory receives the grammar registry followed by the supplied arguments and returns a disposable. Put node callbacks inside that module; do not send functions from the renderer. Registration captures injection disposables for rollback, and package teardown must dispose the module registration. Module code must not use DOM APIs or renderer package singletons.

`setRootLanguageRanges(buffer, { module, method, params })` registers a portable root-range policy. Its exported synchronous function receives the current immutable PieceTree snapshot and params, returning ranges or `null` for the whole source. An empty array excludes all source. The policy follows grammar changes and reevaluates against each new text state. Disposing an obsolete registration cannot remove its replacement. Renderer callbacks are not accepted by the worker backend.

For scheduling, edit latency, pathological lines and runtime recycling, run `npm run test:only -- benchmark/syntax-system-spec.js` with `LUMINE_SYNTAX_SYSTEM_BENCHMARK` set to a JSON object containing `out` and `label`. Optional `cases` selects `small-edits`, `competing-parses`, `long-line`, `repeated-close` and `injection-viewport`. The last case measures exact visible colors and whole-document settlement independently, using HTML with a short visible script and large offscreen scripts. Set `injectionBlocks` and `injectionRows` to vary the workload. The benchmark records colored DOM updates, animation-frame observations, exact syntax completion, runtime capacity and source checksums. Use the same parameters and isolated package profile for before/after runs. A first colored frame on a long line may be provisional or limited. The frame probe observes renderer animation callbacks.

Run `npm run test:only -- benchmark/syntax-worker-scroll-spec.js` in an isolated profile with the desired package sources available. Set `LUMINE_SYNTAX_BENCHMARK_CONFIG` to a JSON object with `file`, `out`, `packages` (package names), and `backend` (`worker` or `inline`). Optional `minimap` shows the minimap, `synthetic` substitutes a small unsaved JavaScript buffer, `gesture: "thumb"` exercises the custom scrollbar input path, `delta` selects pixels per event (before the Alt multiplier for wheels; default 100), and `interval` selects milliseconds between events (default 16.667). Thumb movement reverses at document edges so a short file cannot report success merely by remaining at EOF. The benchmark activates every listed package and checks that the input file's hash is unchanged.

The benchmark covers the middle, end and a direction reversal, recording prepared coverage, colored DOM spans, frame intervals, callback delay, input delay and renderer paint-packet costs. Input timers are queued before the gesture so slow dispatch cannot silently reduce the requested input rate. Summaries exclude the settling period after the last wheel event. These probes add measurement overhead; packet cost is not the whole frame cost, and full coverage alone does not establish a frame-rate improvement.

Set `trusted: true` to inject mouse events through Electron's spec-window input API. Thumb tests then grab the actual scrollbar and move the pointer; they start in the middle and include both directions and reversal. The benchmark verifies movement, compares painted and logical viewport positions, and samples scope classes from the rendered DOM wherever cached coverage is available. Missing coverage is reported separately from a mismatch between cached scopes and displayed scopes. A frame with no colored spans can contain naturally unstyled text, so interpret it alongside scope mismatches and coverage rather than as proof of a rendering defect.

A complementary normal-window probe avoids relying solely on the spec runner. Launch an isolated window with `node script/drive.js launch <fixture> --home <scratch-profile> --port 9247`, provision its package links, and run `node benchmark/syntax-worker-scroll.js <config.json>` with `{ "port": 9247, "out": "<results-directory>", "gesture": "wheel", "warmup": 1000 }`. Use `gesture: "thumb"` for custom scrollbar dragging, `warmup: 0` for a cold destination and `capture: true` to save actual compositor frames as PNGs. Input dispatch is paced independently of its acknowledgements. The report observes every visible mounted row, records active packages and cache occupancy, and verifies the fixture hash. Captured frames contain the real document and remain local test artifacts. Plain-span counts alone are not correctness assertions: naturally unstyled content must be distinguished from missing cached scopes.

# Syntax analysis ownership

The editor uses one worker per window to own Tree-sitter parsers, WASM trees, injection layers and queries. The renderer owns the authoritative TextBuffer, selections, undo history and presentation. There is no second renderer syntax tree. The inline backend remains available for parser tests and controlled performance comparisons. The Jasmine runner defaults to inline for engine-level fixtures; set `LUMINE_SYNTAX_EXECUTION=worker` to run package scenarios against the application backend.

The editor manifest declares the optional packages used by integration specs in `specPackages`. A full workspace resolves them from sibling repositories. In a standalone checkout, run `node script/install-spec-packages.js --package . --home <isolated-home>` and run tests with `LUMINE_HOME` pointing at that home. CI provisions it automatically. These test packages remain outside the bundled distribution.

## Document synchronization

A document opens from an immutable text snapshot, sent in strings of at most 65536 UTF-16 code units. Subsequent edits preserve their exact offsets and source revision. Small transactions take one message; larger transactions use acknowledged packets containing at most 128 changes and 65536 inserted code units. A large individual insertion is split into text packets. The worker applies the complete transaction atomically and keeps analyses waiting until it commits. Its mirror does not retain editor undo history.

Responses identify the source revision and syntax generation. Grammar, query, configuration, path and root-range-policy changes invalidate pending requests even when the text is unchanged. Closing a document cancels its streams and releases its worker session. An unexpected worker crash permits one recovery from authoritative renderer snapshots; another crash disables analysis instead of entering a restart loop. The idle worker terminates after the last document has been released.

## Scheduling and resource budgets

Parsing resumes in slices under one shared 4 ms allowance per worker turn. A suspended parse occupies no concurrency slot. The scheduler rechecks the active document between slices, preserves FIFO ordering at equal priority and gives waiting work a turn after 100 ms. Injection layers share the same scheduler and revision budget as their root. These are cooperative allowances: Tree-sitter must reach a progress callback before yielding, so they are not a hard upper bound on one native call.

Each revision has a 30 second active parsing allowance, excluding scheduling, transport and consumer waits. The runtime also stops a parse when growing WASM memory reaches 85% of its configured maximum, before the allocator's hard limit where possible. Diagnostics distinguish `parse-budget`, `memory-pressure` and a fatal runtime failure. Memory measurements describe allocated linear-memory capacity, not live allocations or an individual document's retained memory. A runtime that reserves its full capacity at startup cannot use growth as a pressure signal and retains the hard-failure path.

Closing a session that caused at least 64 MiB of observed capacity growth requests recycling when the runtime still holds at least 512 MiB. Recycling waits for 750 ms without foreground interaction and for outstanding requests to finish, then reconstructs surviving documents from their authoritative snapshots. Fatal failures and memory pressure use immediate recovery because their runtime cannot safely continue. Ordinary close-time recycling does not consume the unexpected-crash recovery allowance.

Queries have separate work limits: by default 25 ms, 4096 in-progress matches, 16000 returned results or captures, and 65536 UTF-16 code units for an individual predicate text read. Injection query predicates allow up to 1048576 units so ordinary large comments can retain exact language routing; extracted language names and scope predicates keep the smaller cap. Presentation permits a 50 ms query pass in the worker to accommodate dense ordinary source. Query result limits are checked after the binding collects results; they are not an allocator limit. Source windows and native progress checks bound the preceding work. Regex predicates and custom JavaScript callbacks must still be written to terminate promptly. Text predicates either inspect the complete permitted text or fail; they never receive a truncated prefix with altered semantics.

An exhausted exact query reports `ERR_SYNTAX_QUERY_BUDGET`; an editor or buffer analysis returns `null`, and consumers discard any staged output. Presentation may publish limited coverage with its reason, and optional fold warming can stop without affecting editing. A presentation timeout receives one fresh attempt after yielding, with the same deadline; persistent timeouts and structural limits remain explicitly limited. Visible timeout-limited paint gets up to three delayed recovery attempts after 100, 500 and 2000 ms, behind missing foreground coverage. Hiding or releasing the view cancels its wakeup; edits and syntax changes discard old attempts. Revisiting an exhausted range grants a new bounded cycle. Structural limits never retry automatically. Incomplete query results never enter the exact-result cache. Failure to establish required injection topology still makes document analysis unavailable because exact semantic answers cannot assume missing languages.

Deadlines gate admission, native progress and further predicate work. A complete bounded result is not retrospectively discarded because its completion check ran late; cancellation and structural limits still invalidate it. A timed-out injection window can retry twice, yielding and rechecking its source identity before each attempt. Each attempt stages its records independently and merges only on completion. Small exact scope queries allow one fresh attempt. None of these retries increases a query's individual deadline or retries a text, match or result limit.

## Analysis failures

Parser initialization and settlement failures quarantine the affected document. Its selected grammar and language settings remain intact, but the replacement language mode owns no syntax session, highlighting or syntax folds. Editing and saving remain available. Pending analyses finish with `null`, and subsequent requests return `null` without queuing work. Package programming errors still reject; a valid analysis returning an empty array remains distinct from unavailable analysis.

Worker-owned background updates report failures through the same structured channel even when no view or analysis request is waiting. A current failed update produces one owner notification, without a raw console error; a newer revision can supersede a queued obsolete failure. Exhausted required query work reports `query-budget` with its specific reason. Private previews retain their own failure state and propagate errors that require recovery of the shared runtime.

An Emscripten abort or WebAssembly runtime trap poisons the entire worker runtime. The worker reports a structured diagnostic with the current document, operation, revision, grammar and available memory measurements. The renderer quarantines the responsible document, terminates the worker and restores the other documents from current text snapshots. When attribution is unavailable, all affected documents are disabled rather than replaying unknown failing work. A memory-limit diagnostic means the runtime stopped with its linear memory at the configured maximum; it is not inferred from the text `Aborted()` alone. Runtime stderr is retained in bounded diagnostics rather than printed repeatedly.

Each quarantined document receives one warning with diagnostic details and a Retry Analysis action. Edits, scrolling and configuration updates do not retry it automatically. `editor.retrySyntaxAnalysis()` explicitly restarts from current text and returns whether a retry was started; changing to another grammar also replaces the failed mode. Closing or replacing that mode dismisses its warning.

`editor.getSyntaxAvailability()` returns `{available: true}` when analysis is enabled, `{available: false, reason: "none"}` for None, or `{available: false, reason: "failure", failure}` after an infrastructure failure. Enabled analysis may still be parsing; use `whenGrammarSettled()` for readiness. `editor.onDidChangeSyntaxAvailability(callback)` observes language-mode replacements. Consumers must cancel pending UI work and clear decorations or staged stream output when availability becomes false. This contract applies to every split sharing the document.

## Package analyses

Use `editor.analyzeSyntax(modulePath, method, params, options)` for operations tied to an editor, or `buffer.analyzeSyntax(...)` for shared document data that must survive closing one split. The module path must be absolute. Params are cloneable data. An invocation returns a promise; `null` means it became obsolete. Parse failures also return `null`, while programming errors reject the promise. Editor analyses include pending automatic indentation before acquiring syntax. Consumers must still validate selections and their own UI or service lifetime before applying an answer.

```js
// Renderer-side package code.
const ranges = await editor.analyzeSyntax(
  require.resolve("./syntax-analysis"),
  "findCalls",
  { name: "print" },
  { signal },
);
```

```js
// syntax-analysis.js: runs beside the parser, without DOM or editor globals.
exports.findCalls = (context, { name }) => {
  const root = context.getRootSyntaxNode();
  if (!root) return [];
  return root
    .descendantsOfType("call")
    .filter((node) => node.childForFieldName("function")?.text === name)
    .map((node) => ({ start: node.startPosition, end: node.endPosition }));
};
```

The read-only context provides document reads through `context.buffer`, editor-style text and coordinate helpers, the root node, node lookup, query capture groups, scope ranges, comment delimiters, fold queries and indentation hints. `context.signal` is aborted when the invocation ends. Do not retain nodes, cursors, context methods or unfinished asynchronous work beyond that lifetime. Poll the signal and yield during long JavaScript loops. DOM operations, editor mutations, package-manager access and renderer closures belong outside the analysis module.

Renderer methods that expose raw nodes or query captures are restricted to the inline backend and throw with worker syntax. Move that computation into an analysis module instead of requesting cloned nodes or relying on an empty result. The same pure module runs beside the inline parser in comparison tests.

Return plain data, arrays, maps or typed arrays. Point and Range values become plain coordinate records. WASM nodes, functions, accessors and other class instances are rejected rather than transported as unusable handles. Convert coordinates with `Point.fromObject` or `Range.fromObject` when the renderer needs those classes.

For large results, the analysis receives `{ signal, emit }` as its third argument. Await every `emit(packet, transferList)` and keep each packet bounded. The renderer supplies `options.onChunk(packet)`, which may return a promise. Acknowledgement follows that promise, so decoding and consumer work participate in backpressure. The promise returned by `emit` resolves to the consumer's cloneable acknowledgement value. This lets a worker scan resume from a renderer-owned handler's consumed offset without serializing that handler. Do not accumulate raw packets and then decode the whole result in one final renderer loop. Return a small completion summary; discard accumulated output if the final result is `null`.

`context.scanGrammarQueryCaptures(type, { batchSize })` is an async iterator over `{ grammar, captures, layerId, last }` packets. It scans 8192-code-unit source windows and emits at most 256 captures by default; `batchSize` accepts 1–4096. Captures remain native nodes inside the analysis owner. Consume and convert them before requesting the next packet, and release per-layer state at `last`. Genuine duplicate captures are preserved. Edits, grammar or query replacement, cancellation and query exhaustion terminate the scan instead of returning a successful partial result. The symbol provider uses this path to retain plain symbols and active containers rather than an array of every raw capture.

Bulk indentation uses `mode.scanSuggestedIndentation(ranges, tabLength, options)`, an async iterator over batches of `[row, level]` entries. Ranges are ordered, disjoint, inclusive row pairs; a `null` level means preserve that row. Options include `batchSize` (1–4096, default 256), `signal`, `isCurrent` and `preserveLeadingWhitespace`. The iterator preserves virtual indentation across packets and disjoint ranges, including references to distant earlier rows. It retains changed levels in compact pages rather than building a whole-document Map. Worker transport holds at most one unacknowledged batch. Breaking iteration cancels the producer; source or configuration changes abort it. Apply the completed plan through a cancellable editor transaction that rolls back if the stream fails.

## Exact semantics and presentation

`getScopeDescriptorsForBufferPositions` and `getCommentDelimitersForBufferPositions` query many positions in one bounded operation, including positions outside visible rows. They return `null` when superseded. Use them for semantic decisions. Fold, syntax-scope, token, paragraph and comment queries can resolve asynchronously with worker syntax; await them before changing editor state. `getSyntaxSnapshotToken()` supplies an opaque identity for settled semantic caches and returns `null` while syntax is pending.

Exact point lookups query one UTF-16 character, extending across a surrogate pair or CRLF when necessary. Enclosing captures and covering injection layers retain their semantics even when they have no boundary inside that window. Scope range adjustments can resolve conservative finite-width regexes through bounded source slices, such as finding the first opening brace of a large CSS rule; unsupported expressions retain the full-text guard. Grammar predicates should inspect a small structural token when they need only a prefix: Python string classification reads `string_start`, while keeping its native filtering and complete body scope.

Synchronous scope reads remain presentation reads: they use prepared coverage and may show retained scopes while a new revision is being parsed. They cannot be used to claim an exact AST result. Rendering requests belong to their view owner, including a separate minimap owner. `requestHighlightingForScreenRows(owner, start, end)` prepares the view; pass that owner to `tokensForScreenRow` and an optional `maxTokens` to bound token conversion. Release coverage with an empty range. Scope boundaries stream in packets of at most 4096 events. A range contains at most 128 rows and normally at most 16384 UTF-16 code units; a pathological single row remains one presentation unit but its query window is limited to 2048 units. Each completed range publishes immediately, and its acknowledgement selects the next missing range from live requests. Visible editor splits precede their prefetch, followed by minimap requests and single-line measurements. Measurement reads do not request prefetch. The surrounding lead follows approximately 120 ms of measured row movement, bounded between 128 and 1024 rows, with 128 rows retained behind. Native scrollbar input paints ready cached destinations synchronously. Missing destinations start preparation before the scheduled frame and coalesce painting without dropping subsequent input positions. Stable native scrollbar positions are synchronized before token DOM replacement, avoiding a forced layout of the newly colored rows during native position readback. Unchanged coverage is reused, and highlighting does not wait for scrolling to stop or for a minimap batch to finish. Row reads locate scope boundaries with binary search and reuse bounded lazy checkpoints instead of replaying the whole tile prefix for every row.

Ordinary edits receive the exact result as soon as it is available; the renderer adds no fixed debounce delay. Existing colors remain visible while replacement work runs. If full parsing does not settle within a 4 ms grace period, a visible request may independently parse a complete document of at most 16384 code units. It retains the source path and full lexical context, including comments, strings and injected languages beginning outside the viewport. Larger documents wait for their full syntax tree: fixed-size context snippets cannot prove correct lexical state. Its colors remain explicitly provisional until the owning document settles. Previews fill only uncached gaps and never replace retained, edit-adjusted colors. A preview whose highlight query is incomplete publishes nothing; missing captures cannot be treated as plain text. It supplies no semantic nodes, folds, grammar metadata or indentation hints. Exact parsing supersedes it, and edits or disposal release its private tree. Explicit root-range policies skip this preview because their source context cannot be reconstructed safely.

Paint fragments carry `quality: "exact" | "provisional" | "limited"` and an optional reason. The worker mode's `getHighlightingStatus()` reports current coverage separately from retained colors. Matching revision, grammar generation and presentation identity are required before coverage can be called ready. Those identities do not prove that two paint results are equal: publication compares effective scope stacks and invalidates changed screen rows even when the incoming tile overlaps already prepared coverage. Identical rows keep their cached screen lines, and provisional paint neither rebuilds retained rows nor consumes pending exact invalidations. A limited result cannot replace exact colors with the same revision, grammar generation and presentation identity; its uncached or non-exact remainder is still recorded, so budget exhaustion cannot cause an endless request loop. Coverage and gap lookup use the same identity and optional quality filters. A completed full AST does not imply that an arbitrarily long line has complete highlighting. Semantic consumers always acquire settled syntax and never use the provisional tree.

The renderer retains up to 256 scope fragments under a 512000-event allowance and an estimated 32 MiB budget for the active document, including checkpoints and pending edit metadata. Inactive documents use 128000 events and 8 MiB; losing focus immediately evicts unprotected fragments over that allowance. Focus restores background warming within the larger allowance. Primary visible ranges and the packet being published remain protected, so required coverage may temporarily exceed the estimate. The query cache has a separate estimated 2 MiB allowance. Neither estimate measures native WASM tree storage. When foreground requests are satisfied, the worker prepares missing 128-row fragments near the visible editor, within 16384 rows in each direction. Optional warming pauses when it causes eviction or exceeds its allowance, preventing repeated requests for coverage that cannot remain cached. A genuine viewport or source change permits new warming. Each packet acknowledgement rechecks current foreground requests. Folded views do not warm hidden interiors, measurements do not initiate background preparation, and hiding an editor releases its viewport request. Edits before a retained fragment accumulate a row offset instead of walking all its scope events; reads translate only consumed events, while partial replacements materialize the affected fragment.

For multiline completion edits, track inserted ranges through additional edits and call `autoIndentBufferRowsAtRows(rows, { groupWithPrevious: true })` after the transaction. The sparse plan applies once against one revision. Independent edits or indentation-setting changes cancel the correction. Automatic newline indentation follows marked rows through continued typing in the same editor and remains part of its undo operation.

Interactive vertical scrolling keeps one stable preparation target and the latest requested destination. A completed viewport is published with its text and scopes together, while the worker prepares the newest destination. New input cannot repeatedly abandon the current preparation, and a frame deadline cannot replace colored text with an uncolored viewport. Cached native-thumb destinations remain synchronous; wheel input commits within its animation frame. Completed coverage is reserved until publication and released on cancellation, detachment or destruction. The native thumb follows requested input independently of the displayed viewport. Layout-driven updates retain the bounded one-frame preparation path. Prefetch publishes only uncovered or changed ranges; already current coverage and touching offscreen ranges do not redraw the viewport. Colors arriving for mounted lines update those lines immediately, preserving their scroll transform and decorations even while a newer destination is waiting.

A streamed color tile publishes before its fold queries. Fold lookup runs while the existing color acknowledgement is in flight and sends a separate bounded notification; it does not add another acknowledgement round trip. Fold notifications carry the session revision, grammar generation and presentation identity, and obsolete replies cannot roll the renderer generation back. Foldability updates refresh gutter state without invalidating colored screen lines.

## Grammar modules and root ranges

Register dynamic injections through `lumine.grammars.registerSyntaxModule(require.resolve("./injections"), { method: "register", args: [] })`. Its exported factory receives the grammar registry followed by the supplied arguments and returns a disposable. Put node callbacks inside that module; do not send functions from the renderer. Registration captures injection disposables for rollback, and package teardown must dispose the module registration. Module code must not use DOM APIs or renderer package singletons.

`setRootLanguageRanges(buffer, { module, method, params })` registers a portable root-range policy. Its exported synchronous function receives the current immutable PieceTree snapshot and params, returning ranges or `null` for the whole source. An empty array excludes all source. The policy follows grammar changes and reevaluates against each new text state. Disposing an obsolete registration cannot remove its replacement. Renderer callbacks are not accepted by the worker backend.

## Scroll benchmark

For scheduling, edit latency, pathological lines and runtime recycling, run `npm run test:only -- benchmark/syntax-system-spec.js` with `LUMINE_SYNTAX_SYSTEM_BENCHMARK` set to a JSON object containing `out` and `label`. Optional `cases` selects `small-edits`, `competing-parses`, `long-line` and `repeated-close`. The benchmark records colored DOM updates, animation-frame observations, exact syntax completion, runtime capacity and source checksums. Use the same parameters and isolated package profile for before/after runs. A first colored frame on a long line may be provisional or limited; it must not be reported as complete document highlighting. These API-driven edits and renderer observations are not operating-system input latency or compositor captures.

Run `npm run test:only -- benchmark/syntax-worker-scroll-spec.js` in an isolated profile with the desired package sources available. Set `LUMINE_SYNTAX_BENCHMARK_CONFIG` to a JSON object with `file`, `out`, `packages` (package names), and `backend` (`worker` or `inline`). Optional `minimap` shows the minimap, `synthetic` substitutes a small unsaved JavaScript buffer, `gesture: "thumb"` exercises the native scrollbar event path, `delta` selects pixels per event (before the Alt multiplier for wheels; default 100), and `interval` selects milliseconds between events (default 16.667). Thumb movement reverses at document edges so a short file cannot report success merely by remaining at EOF. The benchmark activates every listed package and checks that the input file's hash is unchanged.

The benchmark covers the middle, end and a direction reversal, recording prepared coverage, colored DOM spans, frame intervals, callback delay, input delay and renderer paint-packet costs. Input timers are queued before the gesture so slow dispatch cannot silently reduce the requested input rate. Summaries exclude the settling period after the last wheel event. These probes add measurement overhead; packet cost is not the whole frame cost, and full coverage alone does not establish a frame-rate improvement.

Set `trusted: true` to inject mouse events through Electron's spec-window input API. Thumb tests then grab the actual scrollbar and move the pointer; they start in the middle and include both directions and reversal. The benchmark verifies movement, samples scope classes from the rendered DOM, and records whether a missing scope followed an expired paint deadline. `frameDeadline: false` disables that waiting policy only in the isolated benchmark editor for comparison. A frame with no colored spans can contain naturally unstyled text, so interpret it alongside scope mismatches and coverage rather than as proof of a rendering defect.

A complementary normal-window probe avoids relying solely on the spec runner. Launch an isolated window with `node script/drive.js launch <fixture> --home <scratch-profile> --port 9247`, provision its package links, and run `node benchmark/syntax-worker-scroll.js <config.json>` with `{ "port": 9247, "out": "<results-directory>", "gesture": "wheel", "warmup": 1000 }`. Use `gesture: "thumb"` for native scrollbar dragging, `warmup: 0` for a cold destination and `capture: true` to save actual compositor frames as PNGs. Input dispatch is paced independently of its acknowledgements. The report observes every visible mounted row, records active packages and cache occupancy, and verifies the fixture hash. Captured frames contain the real document and remain local test artifacts. Plain-span counts alone are not correctness assertions: naturally unstyled content must be distinguished from missing cached scopes.

# Language editing settings audit, 2026-10-31

Reviewed all 78 active language packages and their 119 grammar descriptors after the [indentation audit](grammar-indentation-audit-2026-10-31.md). Runtime settings improved in 49 packages; two further packages gained tests or isolated test dependencies for deliberately retained behavior. The other 27 packages retain their reviewed settings. The review covers comments, automatic character pairs, word boundaries, file and interpreter detection, injection scopes and the editor APIs consuming those settings.

Reference behavior comes from [Zed language configurations](https://github.com/zed-industries/zed/tree/main/crates/grammars/src) and [Neovim filetype plugins](https://github.com/neovim/neovim/tree/master/runtime/ftplugin), with per-language links below. Their behavior was adapted to Lumine's actual scope and settings contracts. No upstream implementation was copied. Parser sources, Wasm binaries, formatting preferences and user configuration are unchanged by this settings phase.

## Behavior

Comment commands now distinguish supported line comments, structured block-comment metadata and formats without comments. Python triple-quoted strings and MATLAB standalone block delimiters are not offered as generic wrapping comments. Embedded JSX code gets nonvisual scope metadata before final lexical captures, preserving its highlighting and enabling the correct comment syntax inside expressions. Literate CoffeeScript similarly keeps prose and embedded code policies separate.

Pair lists contain only syntax supported by each language and Lumine's two-character pair contract. A new scoped bracket-matcher.autocompleteDisabledCharacters setting disables automatic insertion, skipping, wrapping, paired deletion and newline handling for selected opening characters while preserving matching and explicit bracket commands. Rust angle brackets and ambiguous apostrophes in Haskell, Scala, Julia and MATLAB therefore retain navigation without inserting unwanted closing characters. Changing the preference also cancels a pending automatic interpolation action.

Word boundaries include identifier punctuation where it belongs to the language, including JavaScript private names, GraphQL variables and hyphenated stylesheet or configuration identifiers. File recognition uses specific extensions, modelines and actual interpreter positions: an interpreter name appearing only in another command's arguments does not select that language. Windows executable suffixes are accepted only for verified runner forms. Existing user file associations continue to take precedence.

## Verification

All 78 full language-package suites pass 1926 specs with no failures in isolated Electron processes. The settings phase adds 148 focused behavioral cases within those suites. Changed packages pass ESLint, formatting and packaging checks, including independent provisioning of declared test peers. The bracket-matcher provider passes all 263 default-mode specs and 13 targeted worker-mode specs covering selective pairs and pending interpolation lifetime; its audit-policy checker passes 10 Node tests.

Editor integration passes 268 focused specs covering grammar queries, conservative indentation and inline/worker relative paste, plus all 429 Node Tree-sitter runtime and syntax-worker tests. Query compilation covers all 119 workspace descriptors and 43 bundled descriptors. All 108 Wasm assets pass the ecosystem builder's consistency checks. Focused package and worker cases overlap full suites and are not added again.

The provider CI retains a documented, exact-version exception for a reviewed development-only ESLint dependency advisory; production dependencies and new advisories remain blocking. The [audit policy](https://github.com/lumine-code/bracket-matcher/blob/4ee45ca5fb4b44aaf1429c30e4f803c7ab5b9ac4/docs/dependency-audit.md) records the affected versions, reachable options and removal condition. This is not a claim that the unfiltered development audit has no findings.

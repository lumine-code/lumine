# Large document search

Text search operates on immutable PieceTree snapshots. It does not flatten the document, build one marker per result, or treat a partial match list as a complete result set. Offsets and limits below count UTF-16 units, not encoded file bytes.

`TextBuffer.createSearch(regex, {range, signal})` captures a revision. Its session exposes `matches()` (an asynchronous iterator), `collect({limit, onProgress})`, `matchAt(index)` and `findNear(offset, {backwards, inclusive})`. `collect` counts all matches while retaining at most `limit` presentation ranges and navigation checkpoints at text-window boundaries and every 1,024 results. Progress carries `complete: false`; only a completed scan supplies an exact final total. An edited or destroyed buffer rejects with `ERR_STALE_SEARCH`; cancellation rejects with `AbortError`. The older asynchronous find methods retain their invocation snapshot and their existing array-returning contract.

Literal expressions, including escaped newline sequences and Find's whole-word wrapper, use windows with overlap derived from the exact maximum match width. Expressions proven unable to consume LF run against complete line batches. Their captures, assertions and anchors use the native JavaScript regexp engine. Other expressions require a single native input, limited to 8 Mi units. A line-local expression whose single line exceeds that limit also rejects. Unsupported searches report `ERR_SEARCH_INPUT_TOO_LARGE` and suggest a narrower selection or an appropriate literal/line-local query. No fixed overlap is used to approximate unbounded multiline regexes, lookbehind or backreferences. Synchronous compatibility methods use the same bounds and semantics; they do not offer asynchronous execution or cancellation.

Only provably literal matching executes on the main thread. Nonliteral asynchronous expressions execute in an isolated worker, including expressions with bounded but expensive backtracking. Each worker batch has a one-second deadline and can be terminated on cancellation. Exceeding that budget rejects with `ERR_SEARCH_TIMEOUT`. Text traversal and result delivery yield after approximately four milliseconds of main-thread work, including windows containing no matches. Chromium workers are used in the renderer and Node workers in standalone core tests.

Search Panel uses asynchronous sessions for large buffers and dense results. Counts and navigation are independent of presentation. At most 2,000 matches around the viewport plus the current match receive markers. Find Next and Find Previous continue through the entire document. Before counting reaches the cursor, proven non-overlapping literals and line-local expressions can navigate locally; the current ordinal remains unknown until counting supplies it. Self-overlapping literals retain the global non-overlap phase through checkpoints instead of restarting at an arbitrary offset. Select All explicitly reports its 2,000-selection limit rather than silently selecting a prefix; Replace All is not constrained by the presentation limit.

`TextBuffer.replaceAllMatches(regex, replacement, options)` prepares output as shared snapshots and bounded text blocks, then commits one undo operation. It expands captures and ECMAScript prefix/suffix references against the original source. It keeps detached marker indexes during preparation so unchanged gaps, endpoint bias, invalidation and CRLF boundary behavior survive the atomic text publication. Marker transformations follow matches in forward source order, consistently with the independent-edit API and buffer search panel regardless of match count. Cancellation, text changes or changed selections/markers discard the plan before mutation. The operation retains participating marker snapshots for undo/redo. Custom range trackers requiring intermediate live text reject atomic Replace All explicitly; Replace Next retains the ordinary single-edit path. A preserve-case transformation of an oversized prefix/suffix substitution also reports an explicit limit before mutation.

Prepared and normalized change events expose `oldTextSource` and `newTextSource` without allocating strings. These snapshot fields are non-enumerable to preserve existing event shapes. Legacy `oldText` and `newText` getters remain available, subject to the explicit string-materialization limit. Postcommit observer failures still finalize dirty state, deferred display updates and marker events; replacement reports `ERR_REPLACE_OBSERVER_FAILED` with `committed: true` and the replacement count, and the completed operation remains undoable. Consumers handling arbitrary document sizes should use snapshots and bounded reads.

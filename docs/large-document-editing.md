# Large document editing

Large-document editing is independent of grammar selection. None disables syntax analysis; it does not replace the text model or disable text search, editing, undo, recovery or file operations. The automatic grammar threshold remains documented in [Large files and grammars](large-files-and-grammars.md).

## View policy

With `editor.largeFileOptimizations` enabled, documents containing at least 32 Mi UTF-16 units or 300,000 buffer lines use an unwrapped view by default. Once active, that policy remains until both dimensions fall below half their entry thresholds, so editing near a threshold does not repeatedly rebuild the projection. The setting does not change document contents or its grammar. Mini and automatically sized editors also use this bounded projection above the same thresholds, even when ordinary large-file optimizations are disabled. They retain their requested sizing settings, but their viewport stops growing and allows internal scrolling; ordinary sizing resumes after shrinking below the exit thresholds. Automatic height is bounded by half the window height or 400 px, while retaining at least one line, and automatic width by the window width or 1,024 px.

Toggle Soft Wrap explicitly to enable wrapping in an individual large document. That choice survives splits and session restoration; splits may subsequently choose different wrapping. Explicit wrapping retains exact layout semantics and can require processing preceding text to establish a distant screen row. It therefore has a different cost from the default direct row projection. A line whose LF-delimited span exceeds the runtime string limit always uses the bounded unwrapped projection until it shrinks; this is checked from persistent line-span metadata before publishing an edit. `maxScreenLineLength` remains the safety wrapping policy for ordinary views; large unwrapped views protect rendering with bounded horizontal windows instead.

## Coordinates and presentation

Document positions and scroll offsets remain logical values. CSS receives a bounded local coordinate space; text tiles, gutters, highlights, cursors, input anchors and overlays share its origin. Native scrollbar extents are bounded and mapped to the logical scroll range. Wheel and keyboard movement retains logical precision, while dragging the native thumb maps its available physical resolution to the whole document.

Vertical overlays can read `TextEditorElement.pixelPositionBeforeBlocksForScreenRow(row, {viewport: true})` and `pixelPositionAfterBlocksForScreenRow(row, {viewport: true})` from the measured row index. These methods do not request horizontal measurement or render the editor recursively. Use the latter for the text's top edge and the former for the next row's boundary when excluding block decorations. Display-layer changes with `origin: "highlight"` repaint scopes without changing row geometry; row-only projections should retain their coordinates for those events.

Unwrapped geometry stores folds as exceptions rather than allocating an entry for every line. Measured row metadata uses a balanced sequence supporting local splices and subtree maxima, and rendered screen-line objects live in a bounded cache. Exact exhaustive width queries remain distinct from the approximate width used to show a viewport.

Very long unwrapped rows render bounded horizontal windows. Logical buffer/screen columns remain unchanged, including tabs, fold markers and UTF-16 boundaries. Visible glyphs are measured using the DOM; shared anchors preserve their positions when windows overlap, including shaped Unicode. Pixel positions in an unmounted portion of such a line are estimates until that portion is rendered. Consumers positioning visible overlays should request positions for the rendered target and refresh after layout. Code needing document coordinates should retain buffer ranges rather than storing estimated pixel offsets.

Unwrapped row measurements cache immutable subtree summaries for tabs, whitespace and pixel estimates. An edit reuses unchanged summaries and reads the changed leaves and visible window instead of rescanning the entire row. Pixel-to-column ties are independent of leaf boundaries, and folded text uses the previous visible character when calculating Unicode widths.

Gutter foldability checks in None read bounded indentation prefixes instead of entire lines. Pathological whitespace prefixes or long gaps can omit a fold indicator during incidental rendering; explicit indentation-fold commands retain exact semantics.

Automatic selection consumers check range metadata before reading text. `InputDialog.setQueryFromSelection()` uses the last selection only when it stays on one buffer line and contains at most 4,096 UTF-16 units; otherwise the existing query remains unchanged. On Linux, automatic PRIMARY clipboard updates accept at most 1 Mi UTF-16 units from the last selection. A larger gesture cancels an older pending update and preserves the existing PRIMARY contents. These limits do not change explicit Copy commands or the selected document content.

Query dialogs retain oversized drafts as immutable sources. `InputDialog` and `SelectList` default to a 65,536-unit query budget, configurable through `maxQueryLength` up to 1 Mi units. `getQueryStatus()` exposes availability and lengths without reading text. When the draft exceeds its budget, parsing, source requests and actions stop, a visible error explains how to resume, and shortening the draft restores normal operation. Explicit `getQuery()` rejects an oversized query with `ERR_DIALOG_QUERY_TOO_LARGE`; hiding and restoring a dialog preserves its complete source.

Package-owned form fields and external parser inputs need their own bounds before calling string APIs. A mini editor is still a full text buffer and can hold a source larger than V8's string limit. Its bounded viewport does not make a full text read safe. Check metadata first, retain the draft on refusal, disable actions that would use stale values, and recover after shortening. Source-aware editing operations should use immutable fragments and cooperative preparation instead of inheriting a protocol's string limit.

Native clipboard text remains a string contract. Newline conversion checks its expanded length before allocation, and clipboard signatures consume bounded chunks. Optional custom clipboard metadata has a conservative 1 Mi serialization budget; exceeding it omits the custom format while preserving the complete plain text. A text payload that cannot be represented raises an explicit materialization error instead of truncating it.

Clipboard planning does not move live selections. Overlapping copy ranges are collected once; cutting also combines touching ranges so each source span is deleted once and the surviving cursors match the copied fragments. Selection merging finishes before history records its final marker state, including edits made directly through source-backed buffer APIs. Undo and redo preserve selection creation order and the active cursor. Destruction observers cannot prevent the remaining marker and selection cleanup from running; their errors still propagate.

Worker-backed multiline paste prepares text, line endings, final indentation and selections in a private document before publishing one edit. The worker forks its existing immutable source and a private copy of the parsed root; only inserted text crosses the boundary in acknowledged chunks of at most 64 Ki UTF-16 units. Indentation results stream in bounded batches, and unchanged source fragments remain shared. While preparation is pending, the visible document and cursors retain their original state. A changed document, selection, grammar or indentation setting cancels the preparation; a failed query publishes nothing. Successful publication emits one final insertion notification per pasted selection and records one undo operation, so no frame exposes the unindented intermediate text. Automatic dedent during typing also skips equal indentation levels, and explicit indentation setters skip identical replaced prefixes without emitting text changes.

Move Line Up and Move Line Down use the same preparation when automatic indentation requires worker syntax. The line move, final whitespace, cursor positions and folds publish together. The original local edits update live marker indexes in one synchronous transaction, while the retained presentation map carries existing colors through movement and indentation. Repeated commands queue in order while syntax is pending. Undo and redo include the whole operation, including cursor-only movement between identical lines.

Enter, insertion above or below the current line, and typing that can trigger dedent use the same atomic publication. Core input events queue before package advice, so a following character, Backspace or Undo sees the completed previous operation. Packages composing insertion with cursor movement can use `transactWithAutoIndentation(callback, options)`: the synchronous callback edits the supplied private editor, and the returned promise settles after final indentation, selections and text publish together. Direct insertion methods may therefore return promises; callers must await them before reading their results or issuing dependent edits.

The private editor uses unwrapped geometry, including existing folds, so positioning distant cursors does not scan unrelated rows. Its syntax candidate retains the parser's time limits and cancellation checks without waiting for a document edit-coalescing turn: the candidate's edits are already complete. Ordinary document parsing still coalesces edit bursts.

Small groups of widely separated prepared edits update their touched layout regions inside one synchronous publication, preserving the unchanged gaps. Dense edits and line transfers retain their combined projection. Display and marker observers still see the completed transaction.

Ordinary typing bypasses syntax preparation when a conservative filter derived from the grammar's indentation query proves that the edited row cannot match a typing capture. The filter preserves literal and simple text-predicate constraints; unknown patterns, dynamic injection languages and changed grammar epochs use the full syntax path. It never computes indentation itself. Small candidate edits cross the worker boundary in one bounded request. Private indentation sessions omit leaf annotation grammars without indentation or descendant queries, while retaining languages that can control indentation. Streamed edits publish only the span from the first changed position to the last, and retain a bounded journal of local syntax edits independently of the parser's restart budget.

Enter at the end of a whitespace-only row inherits its exact indentation prefix without a syntax request. Repeating Enter therefore stays responsive while the parser processes earlier edits. Packages that contribute synchronous insertion cleanup use `onWillPublishTextInsertion` and edit the editor supplied by the event; cleanup then participates in the same publication and undo operation. Completion and snippet consumers use `whenPendingTextInputSettled` before acquiring coordinates behind already accepted input. A newer input or independent edit cancels that wait without cancelling the edits themselves.

Prepared input shares text roots and preserves local marker splices, including edits expanded from compressed batches. It does not snapshot or rebuild every annotation merely to insert a newline. Custom range trackers observe the same intermediate text and ranges as ordinary edits; marker notifications wait until final text, indentation and selections are ready. Undo history stores only layers with `maintainHistory: true`. Provider-owned annotations such as diagnostics remain outside text history, so clearing them cannot be undone by an unrelated text edit. Older history entries containing such annotations are ignored when their layer does not maintain history.

Moving a pane within a window retains its exact editor. Cross-window transfers of large dirty text retain an immutable source in the original window and request acknowledged chunks of at most 64 Ki UTF-16 units. The destination validates every chunk and stages the complete source before committing removal of the original. Cancellation, incomplete data or edits in either window reject the transfer while preserving user content.

## Search and bulk edits

[Large document search](large-document-search.md) documents snapshot queries, progress, cancellation, bounded result presentation, atomic replacements and regex limits. Counts and navigation are separate from presentation markers. A partial count is not an exact total, and a presentation limit must never become an implicit Replace All limit.

Change events expose source snapshots as non-enumerable `oldTextSource` and `newTextSource`. Their legacy string properties remain available for bounded changes. `TextBuffer.canMaterializeText(maxLength)` checks both a caller's budget and the runtime limit before requesting a full string. Prefer `getTextSnapshot()` and bounded reads when size is unknown. An oversized explicit string read fails before allocation with `ERR_TEXT_MATERIALIZATION_LIMIT`.

Syntax scope and indentation operations read source ranges in bounded chunks. Token queries retain their source and materialize their legacy `value` property only when requested. Tree-sitter `Node.text` and `TreeCursor.nodeText` remain explicit string APIs; their UTF-16 range length is checked against the runtime limit before invoking the text callback. Code processing an unknown node size should retain its range and read the document snapshot instead.

Text transactions finalize modified state and marker/display notifications even when an observer fails after publication. Atomic replacement reports a committed observer failure explicitly, so a caller does not mistake an already-applied edit for an operation that left the document unchanged. Undo remains available.

## Intrinsic text commands

Line duplication and movement pass immutable snapshot fragments to the buffer. Duplicating text that requires more than 1 Mi UTF-16 units of line-ending normalization prepares cooperatively before insertion; selection anchors follow normalized CRLF widths and lone-CR line breaks, and cancellation leaves the source untouched. Uniform endings reuse shared roots directly. Upper/lower case conversion and selected transpose read bounded chunks; selections above 1 Mi UTF-16 units prepare asynchronously with a 4 ms scheduling budget and publish only if the original revision and selections remain current. Default Unicode casing preserves contextual final sigma across chunk boundaries. Selected transpose reverses Unicode code points, preserving surrogate pairs and lone surrogates. An empty selection retains adjacent-character transpose behavior.

Bulk indentation and comments prepare ordered source edits and publish one undo operation. Automatic indentation consumes bounded batches over compact row ranges; None carries the virtual indentation of the preceding nonblank row, including earlier planned changes and retained tab stops. Grammar providers must cover every requested row with a finite level or an explicit null; incomplete, stale or cancelled plans publish nothing. Split Selections Into Lines checks a 2,000-cursor presentation limit before changing any selection. Selecting an entire document remains a single unrestricted range.

Large Join Lines prepares ordered edits around line boundaries instead of repeatedly rescanning the growing joined line. Unchanged text remains shared, ordinary markers follow the actual edits, and undo restores the source. Word, subword and paragraph navigation use exact source algorithms; built-in subword runs preserve the existing regular grammar and alternative order. Arbitrary caller-supplied regexes retain the bounded native search contract. Explicit string-returning APIs such as `Selection.getText()` retain their string contract and raise a typed error when a requested string cannot be represented. Synchronous callback-based `replaceSelectedText()` and `TextBuffer.replace()` accept at most 8 Mi UTF-16 units; larger transformations use immutable snapshots and asynchronous edit streams. Selection callbacks read the original snapshot and prepare every replacement before changing text or selections, with separate 8 Mi aggregate input and output budgets. Callbacks must return strings without changing the editor themselves; stale preparation is rejected. A callback failure or an exceeded budget cannot apply an earlier prepared replacement.

Explicit Copy/Cut preflights the aggregate selection length before materialization. Cut prepares the entire clipboard payload, waits for successful native publication and verifies the original document/selection before deleting anything. A failed write leaves document text intact and produces an error notification. Editor commands settle asynchronous results, including arrays of per-selection promises, and distinguish committed observer failures from failed preparation.

Project search still exposes complete line strings in its external result contract. The ripgrep JSON transport rejects a message over 8 Mi UTF-16 units or more than 100,000 matches in one file before allocation of an unbounded result list; the error explicitly identifies incomplete results and recommends buffer search or a narrower query. It never presents truncated matches as complete results. Buffer search has the separate scalable contract described above.

Legacy synchronous scan callbacks retain complete string context. Their `lineText` getter and requested surrounding context reject more than 8 Mi UTF-16 units before materialization; surrounding context also has a 100,000-line allocation limit. The match range and bounded match text remain usable independently of those optional context strings. Snapshot consumers can retrieve their own bounded excerpts.

## Recovery and external changes

Session capture retains immutable text roots. [Session storage](session-state.md) persists bounded content-addressed nodes and publishes root references atomically after the nodes are durable. Subsequent edits reuse unchanged nodes, including history. Periodic autosaves retain undo/redo as well as unsaved text. Cancellation or an interrupted publication cannot replace a previously valid session with an incomplete snapshot.

Fine-grained diffs have allocation and computation budgets. A large difference can use exact shared text in a coarser patch rather than flattening both documents before reaching a timeout. Recovery and reload must preserve the distinction between a saved base, current text and an external file change; a cheaper diff is not permission to lose content or silently overwrite the file.

Reload compares decoded chunks with the captured saved base during a single read. Equal ranges at the same offsets reuse immutable source fragments, and an unchanged file reuses the complete saved root and its cached digest. This avoids retaining another full copy during an unchanged reload alongside the original, current edits and undo history. Insertions or deletions in the external file can shift subsequent ranges and require new backing storage. Equality is checked against the actual decoded content rather than inferred from file timestamps or size; read failures and edits made during a non-forced load retain their existing protection.

## Validation

Structural tests cover sparse multi-million-row edits, persistent sequence invariants, split geometry, folds, CRLF and surrogate boundaries. Renderer tests exercise physical CSS limits on both axes, long-line selections/cursors/IME, Unicode window transitions and direct hit testing. Search tests include documents exceeding the runtime's maximum string length, dense counts, cancellation, regex deadlines, actual replacement geometry and observer failures. Recovery tests include interrupted publication, concurrent references, lease cleanup, corrupt metadata, file conflicts and large undo history.

Performance measurements should use a separate profile, production rendering schedules and unchanged input hashes. Record command time separately from frame callbacks, first result separately from complete counts, and initial recovery storage separately from incremental updates. CPU profiles are diagnostic runs rather than acceptance timings. Local measurements do not establish cross-platform correctness; the regular Windows, Linux and macOS suites remain required.

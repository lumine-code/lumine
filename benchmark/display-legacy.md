# Legacy display benchmark

Run `npm run benchmark:display -- --output ../.dev/benchmarks/display-legacy/<run-id>` before changing display source or the Superstring pin. The runner copies tracked editor source and the exact installed Superstring package into that directory, makes its direct native imports point at the copied addon, and records the SHA, source hash and installed pin. Other dependencies resolve through the current checkout's `node_modules`; keep those dependencies and grammar packages constant across a comparison.

After implementation, run `npm run benchmark:display -- --compare --profile release --output ../.dev/benchmarks/display-legacy/<run-id>` against that same frozen baseline directory. This runs three complete A–B–B–A blocks, six fresh Electron processes for each variant, five warmups and thirty measured samples per case. Run it with builds, tests and other performance workloads stopped. `--release` is an alias for `--profile release`; the default quick profile uses one warmup and three samples for exploratory checks and is not an acceptance gate.

The renderer corpus covers scalar and packed predecessor lookup including input packing, buffer-to-screen mapping, decoration queries and component updates with sorted/shuffled endpoints and cached/uncached/mixed markers. It includes identity, wraps, folds, tabs and 1/16/64/256/5000 endpoints. Long-line cases cover 10k/250k/1M characters, start/middle/end, insert/delete/replace, one/two/four layers and shared copies versus independent layouts. Additional 250k one-layer controls measure insert/delete at all three locations in words, tabs and folded text; the edits stay outside the fold and every sample verifies that it survives. Python cases wait for the actual Tree-sitter transaction before the second component update; plain-text and Python scroll cases are controls.

Each process saves raw samples, runtime versions, loaded addon path/hash and output checksums beside its log. `summary.json` reports pooled medians, p95, fresh-process medians, comparison percentages and deterministic 95% bootstrap intervals over fresh-process medians. A checksum mismatch fails the comparison. Corpus changes are copied identically into both variants and update the manifest's benchmark hash; discard earlier exploratory results when this happens. Production baseline source and its copied native addon are never refreshed.

Accept batch mapping only when a real uncached-decoration case with at least 256 endpoints improves its query median by at least 20% and its confidence interval excludes zero. Accept local invalidation only when the warm 250k/1M plain-text replacement-to-component cases improve by at least 30% and report zero spatial-index updates. Scalar, identity, cached decorations, insert/delete and scroll controls must not regress by both more than 5% and more than 0.5 ms. Review regressions per workload rather than averaging all cases together.
